# 第0/1层数据流图

版本日期：2026-10-03。该图说明系统边界内外的信息流和数据存储，不描述工单或作业状态迁移；后者另见[治理状态图](governance-state.md)。

## 第0层：系统上下文

第0层将数据库应用视为一个整体处理过程，标识业务用户、维护人员、官方数据源及越过系统边界的数据。后台worker和具体存储属于系统内部，将在第1层展开。

~~~mermaid
flowchart LR
  U["E1 普通用户"]
  M["E2 管理人员<br/>ADMIN / MANAGER"]
  O["E3 维护人员"]
  S["E4 官方公开数据源<br/>NYC Open Data"]
  P0(("P0<br/>纽约交通碰撞风险识别与治理管理系统"))

  U -->|"查询条件、地图/统计请求、导出请求"| P0
  P0 -->|"分页事故、统计结果、风险画像、授权结果"| U
  M -->|"批次审核、路口确认、风险计算、工单操作"| P0
  P0 -->|"质量问题、候选证据、风险/工单/审计结果"| M
  O -->|"数据文件、manifest、配置及维护操作"| P0
  P0 -->|"导入/作业结果、健康信息、维护反馈"| O
  S -->|"公开元数据、事故/人员/车辆CSV"| P0
~~~

官方CSV由维护人员取得并提交，或经仓库提供的数据下载入口获取后交给导入流程；箭头只表示文件与元数据输入，不表示系统能修改纽约市官方记录，也不声称实时订阅官方平台。

### 读图说明

P1按授权读取事故、地点、风险画像及数据库统计，不直接写入事实。P2接收原文件、登记manifest及发布授权；解析、质量校验和正式发布由P5执行。P3把来源观察地点与标准路口档案分开，负责候选、人工复核和风险计算请求；P5再读取一致快照，原子发布完整风险结果。P4通过应用授权和数据库函数执行账户操作、治理状态变更及只追加历史。P5是服务器端后台进程，不是用户角色；它轮询数据库中的待办批次，以租约防止失效任务继续发布。P6处理所有维护请求，外部实体不直接修改数据存储。备份从D1/D2读取，恢复只写D5，D4中的私有归档不进入公开仓库。

实际备份同时保存已登记原始文件、风险快照、锁定依赖和迁移版本。凭据通过本机初始化生成，不把源库凭据发布到报告或源码。完成状态以[M7验收记录](../milestones/M7.md)为准。
