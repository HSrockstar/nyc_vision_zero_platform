# ADR 0002：M1 最小工程与本机开发入口

- 日期：2026-09-29。
- 范围：用户本轮指定的最小项目骨架、迁移入口、Windows启动方式；完整M1尚未完成。
- 依据：[计划](../../PROJECT_PLAN.md)、[M0环境](../environment.md)及既有精确锁。

## 实施决定

1. **复用基线**：Python3.12.4、Node24.14.1/npm11.11.0及已验证包版本保持不变。Windows/Linux哈希锁复制到backend；frontend沿用M0全部包解析和integrity，仅改项目名称、版本及运行脚本。新Windows `.venv`从哈希锁安装，M0环境保留。
2. **隔离开发库**：Compose只管理数据库，资源为`vision-zero-dev-db`、`vision-zero-dev-postgis-data`、`vision_zero_dev`，默认绑定`127.0.0.1:55433`；M0的55432端口和资源独立保留。使用已导入的官方不可变镜像ID，不自动下载浮动版本。
3. **本地配置**：bootstrap生成48字节随机源的十六进制密码及工作区标识，写入被忽略的根目录`.env`；存在时先校验且不覆盖。`.env.example`只是样例，不能直接用于连接。
4. **迁移入口**：Alembic配置不含密码，连接通过Settings读取并与根目录.env批准的DSN和端口比对。开发脚本拒绝冲突的进程环境覆盖；随机M1测试库需显式启用，除库名外连接不变。拒绝M0、SQLite、其他数据库、远程主机及URL连接参数。迁移事务内限定search_path=public，排除spatial_ref_sys；默认版本表schema与该搜索路径保持一致，避免反射tiger/topology扩展表或误判版本表待删除。
5. **首个迁移**：`0001_environment`只幂等确认PostGIS扩展并建立迁移版本记录，不创建23张业务表。回退base清空当前版本标记但保留PostGIS扩展和版本表，不执行DROP EXTENSION，避免删除扩展依赖对象；业务回滚策略随后续迁移定义。
6. **开发入口**：PowerShell以脚本路径定位项目，后端/前端前台运行，端口占用时拒绝启动。数据库启停和迁移只允许本机Docker命名管道引擎，拒绝Docker进程覆盖，并核对标签、镜像、端口、数据卷挂载及数据库配置；迁移还要求容器已运行，异常时中止。Stop不删容器或卷；后端监听127.0.0.1，前端只向本机后端代理。
7. **就绪边界**：`/health/live`只测进程；`/health/ready`真实核对数据库、锁定版本、迁移head与空间SQL，失败返回503及固定原因。worker当前仅提供同样的连接预检并退出，没有任务轮询、导入或风险计算。

## 尚未通过的范围

当前只有环境检查API，没有用户与业务API。开发库管理账号暂用于本机迁移和只读预检；迁移/应用/worker角色分离、认证授权、业务约束和函数权限属于M1后续验收，不能把当前连接方式用于正式业务运行。

街道字段字典、UNKNOWN画像建单、在办任务角色变更及幂等摘要等契约仍按 [ADR 0001](0001-implementation-baseline.md) 后续落实。本轮不决定这些业务规则，也没有真实数据导入。

## 验证与回退

实际命令与结果集中记录在 [M1执行记录](../milestones/M1.md)。基础测试拒绝越界连接并覆盖无效配置的503；显式启用的集成测试只在新建随机验证库执行空库、重复升级、base回退与再升级，保留验证库，不回退开发库。

结束开发时对当前终端按Ctrl+C，并运行数据库Stop保留卷。未开始业务迁移前，环境迁移可在专用验证库回退base；不要将此操作当作23表或真实数据的恢复方案。任何后续移除卷、修改已有数据或升级版本须另行说明精确目标和验证范围。

Alembic入口布局参考[官方教程](https://alembic.sqlalchemy.org/en/latest/tutorial.html)，具体兼容性以本机固定版本的实际执行为准。
