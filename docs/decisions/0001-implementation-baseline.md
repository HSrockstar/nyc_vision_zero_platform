## 2. 采用的实施决定

| 编号 | 决定 | 理由与验证边界 |
|---|---|---|
| D01 | PostgreSQL 17 系列 + PostGIS，单体同步 FastAPI + 独立单 worker | 不扩展微服务、Redis、Celery 或机器学习 |
| D02 | Python 3.12.4、Node24.14.1、npm11.11.0；按 environment 精确包版本 | 本地隔离安装和模块冒烟已通过，兼容性不靠版本名称推断 |
| D03 | Python 使用全传递 `==` + 分发文件 SHA-256；npm 使用无范围直接版本 + package-lock + npm ci | Windows40包、Linux amd64/glibc38包分别锁定；Linux干净环境真实哈希安装重放通过 |
| D04 | 数据库基线 PG17.11/PostGIS3.6.4，实测版本后锁官方digest | 已经官方OCI对象校验导入并实测，见database-image.lock.json；旧17.5只作历史证据，原生pull的EOF仍保留 |
| D05 | 初次M0保留材料；后续按用户两次授权将三份旧资料和课程指南归并成S2/S1、删除原文件，计划更新1.2 | 每次先校验压缩备份、形成摘要并复核；保留历史证据，不提前建立业务骨架 |
| D06 | 首次真实导入目标为 2025 年 1 月前 500 起稳定排序事故及完整子明细；随后年度范围固定为2025 | 本轮仅 10 起父样本；API 年度 count 不作为已下载/已导入规模 |
| D07 | Crashes collision_id 为父键；Person/Vehicles unique_id 为正式记录键；源同名代码保存TEXT | 年度键质量及样本证明这些字段不能互换；BIGINT API 按字符串序列化 |
| D08 | P0 不建立人员—车辆直接 FK | 小样本 Person.vehicle_id 匹配 Vehicles.unique_id 而非 Vehicles.vehicle_id；全范围仍待核验 |
| D09 | CSV 为必备离线入口，原文件+表头+范围+哈希+行号+清洗版本构成manifest | 不以错误页面冒充CSV，不用前N行冒充全年，不隐瞒三源范围差异 |
| D10 | 保留 NULL 与真实零；缺坐标仍保留事故；全未知地点按事故ID区分 | 不制造零坐标、零伤亡或统一未知地点；异常原值留暂存 |
| D11 | 观察地点与标准交叉口分开；只有确认路口和有效单一归属入正式排名 | 距离近不证明同一交叉口；50米仅默认参数，人工判断不被重跑覆盖 |
| D12 | 风险按一事故一行的 Crashes 汇总，S=N+3I+10K+5V；V=行人+骑行者伤亡 | V 有意额外加权；不是独立互斥人群、重伤数或未来概率 |
| D13 | 缺任一评分必需伤亡字段，分数NULL、等级UNKNOWN；无画像也不标低风险 | 不能让数据不足产生虚假低风险；阈值[10,30)为MEDIUM |
| D14 | 工单权限=账户当前角色+任务内身份+状态+版本；禁止自审 | 前端隐藏按钮不足；不同管理人员执行与复核，管理员也受状态和自审规则约束 |
| D15 | 数据版本标识过期，成功画像/规则/工单历史不可改；文件和映射快照支持重算 | revision不是时光查询；原文件、规则、代码、清洗和地点匹配版本缺一不可 |
| D16 | 数据库Docker运行；后端/worker和前端在Windows开发 | 用户确认；M1先建立数据库Compose及PowerShell入口，全服务容器交付按需补齐 |

## 4. 追溯及权限的最低验收

完整导入批次必须解释 `read=accepted+rejected+skipped`，原始行数不等于正式表写入数。来源修订创建新原始记录并受控更新，原因槽位清空需去除旧关联；本轮没出现的行不得作为删除依据。

归属修正、交叉口确认/停用与数据发布在同一事务增加分析revision。交叉口用过成功画像后身份冻结，重大修正新建替代对象，旧工单不迁移。纯用户显示名及工单处理不增加事故版本。

认证与权限实现属于M1，治理动作属于M5。数据库迁移/应用/worker角色分离；受控函数的actor_id来自可信后端，不承担用户认证。关键状态写入、历史只追加和SECURITY DEFINER权限须独立检查；本轮未实现或验收这些机制。
