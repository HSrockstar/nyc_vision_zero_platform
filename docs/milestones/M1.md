## 失败与修正

1. 最初无效DSN用例触发SQLAlchemy ArgumentError；配置层原只捕获ValueError。已补充捕获并返回固定错误，测试通过，不输出连接秘密。
2. 首次自动差异检查失败，原生退出码-1：官方镜像search_path为`"$user", public, topology, tiger`，Alembic把可见扩展关系当作业务删除候选。检查只读，没有执行删除。[原始错误](../evidence/M1/autogenerate-initial.log)。迁移改为事务内SET LOCAL search_path TO public，并保持默认版本表schema一致，检查通过。全局search_path不变，public2、tiger34、topology2张关系仍在。[修复日志](../evidence/M1/autogenerate-fixed.log) / [关系计数](../evidence/M1/extension-tables-after.log)。
3. 独立源码审查发现进程环境覆盖、Compose配置覆盖、未核对实际挂载三项P2，复核又指出Docker上下文未限定的条件性P2。已补齐批准目标比对、冲突环境拒绝、容器挂载/配置预检、本机命名管道引擎与迁移运行状态检查，并新增拒绝用例；独立源码复核确认闭合。[审查记录](../evidence/M1/review.md)。
4. Windows5.1模拟检查暴露ConvertFrom-Json数组被额外包裹，导致符合预期的配置被拒绝；已移除外层数组包裹，8项检查及真实MigrationStatus均通过。

仍有Starlette TestClient/httpx、glob10.5.0上游弃用提示；没有换包或压制警告。原生Docker Registry EOF保留为M0已知网络限制，本轮直接复用已校验镜像，没有新下载、绕过访问控制或新增收费资源。
