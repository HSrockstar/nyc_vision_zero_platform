# 秋季课程要求与项目参考摘要（S1）

整理日期：2026-09-29。完整阅读秋季指南18页后，仅保留对“面向 Vision Zero 的纽约交通碰撞风险识别与高危交叉口治理管理系统”有约束或参考价值的内容。**课程要求**来自指南；**项目落实方式**以 [PROJECT_PLAN.md](../../PROJECT_PLAN.md) 为准。文中页码为原PDF物理页，括号内为幻灯片印刷页码。

## 1. 选题与个人项目边界

- 个人任务是设计并开发有实际意义、功能完整的数据库应用系统，以数据库理论和应用开发能力为重点。（第1页，幻灯片2）
- 可以选择城市计算方向，也可以结合个人兴趣自拟题目；题目应有一定新颖性，可以沿用上学期题目。**10月8日前在 Canvas 录入最新题目**。（第2页，幻灯片3）
- 本项目对应城市计算中的交通安全与数据管理应用。事故查询、风险识别和交叉口治理是本项目选择；指南未指定 Vision Zero、风险公式、23张表或具体业务流程。

## 2. 设计与实现必须覆盖的内容

| 课程要求 | 本项目落实方向 | 原文位置 |
|---|---|---|
| 按软件生命周期完成问题定义、可行性分析、需求分析、总体及详细设计、建库与应用实现、功能调试、性能及综合测试、改进完善、运行维护，并撰写对应报告 | 按M0—M8组织设计、实现与真实验证证据 | 第12页（13） |
| 需求分析包括数据字典、数据流图 | 数据来源与字段契约、数据字典、数据流图 | 第12页（13） |
| 分别设计概念模型（E-R图）、逻辑模型、物理模型；考虑规范化和实际应用，一般达到3NF | 实体/联系/基数、关系模式与规范化依据、类型/约束/索引/迁移 | 第12页（13） |
| 建立必要索引，优化程序中的SQL，完成数据库性能测试 | 使用真实查询、执行计划和可复现实验，实验数量由项目自行确定 | 第12页（13） |
| 考虑关系模型三类完整性，详细说明数据关联，适当定义联系与约束；部分约束可按需使用触发器 | 实体、参照、用户定义完整性落实为主键/外键/唯一/检查等约束；触发器按需使用 | 第13页（14） |
| 设置用户管理，按需求划分用户级别，明确各级权限和可操作功能 | 用户管理、三类业务角色、后端授权及数据库权限 | 第13页（14） |
| 根据实际需求设置基本及附加功能；常见功能包括增删改查、统计报表、打印、备份恢复、用户管理、密钥等，也可包含分析与决策支持 | 官方事故导入/查询、治理业务操作、统计/导出/打印、备份恢复；具体功能取舍见计划 | 第13页（14） |
| 独立完成，报告和程序功能完整，设计方法合理，界面友好，系统运行正常 | 作者审核并能够解释设计和代码，以可运行系统、报告及演示相互核对 | 第15页（16） |

常见功能是按需设计的举例，不能推导为“每张表都必须提供全部增删改查”；触发器也是按需选项。指南强调数据库设计、性能和完整系统，未要求训练预测模型。

## 3. 交付、时间与成绩构成

个人系统须提交以下三项。（第15页，幻灯片16）

1. **系统设计与开发报告：不少于1.0万字、不超过1.5万字**，按软件工程要求和格式书写，需求分析及概念、逻辑、物理设计清晰明确。
2. 系统源代码文件。
3. 系统操作、运行的**完整功能录像演示文件**。

教学周与日历日期的对应以课程安排为准；现有M0完成状态不代表已完成题目登记、中期检查或答辩。

## 4. 对本项目有参考价值的内容

- **城市计算路线**：指南图示从城市感知/数据获取，经数据管理、分析到应用服务；智慧交通包括交通事故检测和驾驶行为监测。可用于解释本项目“公开事故数据—关系数据库—统计/风险—治理管理”的定位。（第6、9—10页，幻灯片7、10—11）
- **多源交通数据**：基础设施/车辆人员、动态检测/行为、调查、人口土地经济及天气环境等属于不同来源。可用于说明碰撞数据的覆盖边界；本期只使用已确定的事故三源，流量和天气等不因指南举例而加入。（第8页，幻灯片9）
- **数据入口线索**：指南列出[纽约开放数据](https://opendata.cityofnewyork.us/data/)及[OpenStreetMap区域下载入口](https://download.geofabrik.de/)。（第11页，幻灯片12）三类碰撞数据的实际ID、访问结果和离线方案见 [数据探测](../data_probe.md)；这些入口本轮只按指南保留，未重新验证实时可用性，地图数据下载入口不等于在线底图服务许可。
- **技术可选择**：指南允许B/S、C/S或多级混合结构，列举PostgreSQL等数据库；编程环境和语言可自由选择，Python在示例中。当前PostgreSQL/PostGIS、FastAPI、Vue、Docker数据库及Windows开发方式均是本项目实施选择；指南没有指定版本、框架或容器。（第13—14页，幻灯片14—15）

## 5. 小组调研与个人系统分开管理

课程另有数据管理前沿技术调研：**3—5人小组，提交20—30页PPT**；须列明成员和各自工作。允许深化上学期调研，若沿用并深化，应以1页PPT总结与上学期的主要区别。（第16页，幻灯片17）

这项任务影响课程提交和答辩，但不进入当前个人系统的M0—M8业务范围；不因调研方向而新增向量数据库、RAG或分布式服务。具体调研选题与分工另行管理。
