# ADR 0005：地图与交叉口归属

状态：2026-09-30实施。沿用M1的`location`、`intersection`、`location_assignment`三表和M2正式事故事实，不新建业务表。

## 数据与空间边界

事故始终通过`collision.location_id`关联观察地点。地图只为有坐标的地点绘点；日期区间总数、缺坐标数及原事故列表均保留无坐标事故。地图范围采用经度west/east、纬度south/north且必须递增；单次最多2000点并明确返回`truncated`。附近查询和候选匹配均在SRID 4326点上转换为geography，以`ST_DWithin`按米计算；`location.geom::geography`和`intersection.center_geom::geography`分别有GiST表达式索引。

街道组合只取`location.on_street_name`和`location.cross_street_name`。后者来自官方显示字段CROSS STREET NAME；本库`off_street_name`是地址，不参与配对。街名仅作NFKC、大小写及空白规范化，排序形成无向二元组；不做街道别名或道路层级推断。候选仅处理行政区明确为1—5、坐标及两条不同街名齐全的地点，行政区要求严格一致，未知行政区留待人工调查。

## 候选及确认

`m3-anchor-v1`按`location_id`升序分批，每批最多100个地点。没有附近匹配时，以首个观察点为固定中心创建`DERIVED/CANDIDATE`；默认半径50米，可在20—80米间选择。后续地点必须直接落在固定中心半径内，不因相邻点连续扩张。相同街道组合和行政区内，唯一已确认对象才能自动归属；多个已确认对象时只保留待确认状态和证据，不能按最近距离硬选。拒绝的候选不自动重建；人工拒绝或改派不会被重复生成覆盖。参数、算法版本、候选/确认/拒绝ID和锚点写入归属证据。

ADMIN/MANAGER可确认、拒绝候选并填写依据。确认时同步复核附近生成归属；若新增确认使旧自动归属出现多解，同事务撤回为待确认。人工归属只能指向启用且已确认的交叉口，提交需当前版本和非空理由；无匹配或拒绝可显式解除目标。候选状态、归属及数据版本逐项递增，写入只追加审计。`location_assignment`的地点主键保证单地点最多一个当前归属；所有事故通过该地点共享当前结论。候选中心为数据推导值，不表示官方道路节点，50米参数没有准确率声明。

## 权限与回退

API读接口要求登录；只有ADMIN/MANAGER能生成、确认和改派。数据库app角色只新增交叉口/归属的INSERT、必要列UPDATE和交叉口序列USAGE；worker仍不能改这两表。触发器拒绝应用账号创建已确认对象、非法候选转换、正式归属指向未确认对象、自动覆盖人工决定、归属版本跳跃及非M3数据版本更新。写请求沿用账户事务锁，随后取M3工作流锁，串行化同一工作流；单次候选上限100，本机CLI最多100批且每批单独提交。

迁移`0005_intersection_workflow`仅增加表达式索引、三个保护触发器和最小授权，不改已有事故/地点/来源行。开发库仅前向升级；降级函数只允许命名为随机验证库的专用测试库。若需要撤回开发库上的代码，可停用M3页面/接口并保留0005结构及既有数据，待新的前向迁移处理；不在开发库执行降级或删除候选。
