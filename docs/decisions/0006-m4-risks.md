# ADR 0006：风险运行与历史画像

日期：2026-09-30。范围：M4；沿用23表、原课程规则和`v_risk_profile`，治理任务动作留在M5。

开发库道路身份已复核为95个已确认、1个已拒绝、4个待定，95条有效地点归属覆盖349起事故。M4不扩大候选生成或匹配范围，只读取选定周期内指向启用、已确认交叉口的`AUTO_MATCHED/MANUAL_CONFIRMED`归属。2025全年85,546起事故是覆盖率分母；未归属及缺坐标情况独立显示。首批路口不是全市高危路口普查。

规则`COURSE_V1` v1在M1已初始化：`S=N+3I+10K+5V`，10及30为中/高阈值；V为行人、骑行者伤亡的额外权重。只连接事故与一对一伤亡汇总，避免人员、车辆、原因的多行放大。六个评分必需伤亡字段中任一缺失时，计数保存已知值合计及缺失事故数，视图给出NULL分数、UNKNOWN等级。无事故的路口不生成画像。规则退休仍能查历史，但不能新建计算。

POST创建排队任务，`request-v1`哈希绑定操作者、规则及左闭右开周期；同UUID同内容返回原任务，内容不同返回409。worker使用短事务`FOR UPDATE SKIP LOCKED`领取，120秒租约、20秒独立连接心跳。过期任务标记FAILED；人工重新计算使用新的请求编号，不重复发布原成功批次。默认worker每轮处理一个导入和一个风险任务；`--kind risks/imports`可限定运行范围。

读取使用`REPEATABLE READ READ ONLY`事务，从同一快照取得revision、聚合、覆盖、地点映射、纳入事故的评分字段、CRASHES来源批次及原文件哈希。纳入事故不包含人员明细。受控中间文件独占写入、fsync、原子更名；SHA-256、字节数、画像/映射/输入行数列入manifest。文件位于`.m4-work/snapshots/<批准数据库>/`，按数据库隔离、逐级拒绝重解析点。代码和实际视图定义的哈希记录计算版本；视图定义全文保存在本机快照。备份历史画像时须同时保留这些文件。

发布在独立写事务核验文件、任务编号、令牌、租约、规则/周期，并在账户锁下重新核验请求者仍启用且为ADMIN/MANAGER。全部画像、输入revision、manifest、覆盖摘要、成功状态与审计同时提交。失败回滚后另事务写失败状态；读取接口只暴露成功批次的画像。快照读取后出现新revision时，结果保持旧版本，视图显示`is_stale`。

迁移0006仅增加M4读取、请求及worker发布所需授权与工作流触发器，无新增业务表，不改变官方事实或dataset revision。app只能创建规范排队任务，不能写画像；worker只能更新运行的工作列、插入画像及审计，不能替换请求参数或写地点归属。成功运行/画像沿用M1不可变触发器。旧规则在排队后退休时，worker能正确标记失败，不因规则已退休而卡死在RUNNING。开发库只能前向迁移；随机验证库允许0006→0005→0006复验。

页面按明确周期、规则选择最近成功批次，历史批次分页；画像查询必须指定一个run_id，按分数或事故数稳定排序。切换批次、筛选或请求失败时清空旧表，避免把旧行展示在新批次信息下。停用规则可查询历史，生成按钮禁用。显示覆盖率、缺失、分项贡献及过期说明，不把原始分数称为未来概率。

这是单后端/worker的本机课设实现。当前快照保留供追溯；长期配额、保留清理、备份恢复和生产负载边界留M7/部署阶段。后续若更改评分视图，必须保持旧批次规则语义及版本证据，不覆盖历史公式。
