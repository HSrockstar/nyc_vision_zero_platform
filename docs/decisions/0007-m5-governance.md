# ADR 0007：M5 模拟治理工单与原子状态变更

- 日期：2026-09-30
- 范围：PROJECT_PLAN §12、§15.6、§19.7 的 P0 治理业务。
- 依据：M4 成功且不可变的风险画像、M1 工单与历史关系。

## 建立依据与数据边界

工单从成功风险画像及已确认、启用交叉口建立；服务器生成正式编号，并冻结画像、中心坐标、评价半径、选择理由和 `is_simulated=true`。创建后不替换依据。低、中等级需说明建立理由；UNKNOWN 只能建立 FIELD_SURVEY 调查草稿，不能发布，补齐资料后从新画像另建任务。

模拟任务不表示纽约政府的真实工程，不提供施工授权或因果效果结论。M5 不实施 P1 前后比较、任务重开或终态备注，也不拓展 M6 统计。

## 状态与身份

| 动作 | 原状态 → 新状态 | 允许身份 |
|---|---|---|
| 建立 | 无 → DRAFT | ADMIN / MANAGER |
| 修改、逻辑删除 | DRAFT → DRAFT | 创建者或 ADMIN |
| 发布，选定执行人 | DRAFT → OPEN | 创建者或 ADMIN |
| 重新分配 | OPEN → OPEN | 创建者或 ADMIN |
| 开始 | OPEN → IN_PROGRESS | 当前执行人 |
| 执行记录 | IN_PROGRESS → IN_PROGRESS | 当前执行人 |
| 提交 | IN_PROGRESS → PENDING_REVIEW | 当前执行人 |
| 通过 / 退回 | PENDING_REVIEW → COMPLETED / IN_PROGRESS | 创建者或 ADMIN，且不是当前执行人 |
| 取消 | 任一非终态 → CANCELLED | 创建者或 ADMIN |

MANAGER 可查看所有未删除工单；VIEWER 不访问治理任务。已删除草稿的详情与历史仅创建者或当前ADMIN可见，其他管理人员返回404。完成、取消和已删除任务不得继续变更。前端按 `allowed_actions` 显示操作，后端和数据库函数分别核验身份和状态。

## 事务与恢复

所有写请求含 UUID `request_id`，已有任务变更含 `expected_version`；摘要沿用 `request-v1`，绑定操作者、操作、目标、版本和有效输入。同请求同内容不再次写入，返回原任务的当前授权投影（不保存历史响应快照），不同内容返回 409；并发旧版本返回 409。前端失败后要求主动重新加载，保留原请求号直至请求成功或内容变化。

函数先使用 M1 共同账户事务锁 `76301002`，再锁定任务行，防止执行人分配与账户停用/角色变更交错。任务更新、版本递增、只追加历史和结果登记共用同一事务。创建版本/序号为 1，后续历史 `sequence_no` 与任务版本对齐。历史插入失败应使整项变更回滚。

函数采用 `SECURITY DEFINER`、固定安全 `search_path` 和限定对象名，撤销 PUBLIC 执行权，仅授予应用角色受控入口。应用与 worker 不获得工单/历史直接写权限。随机验证库允许迁移往返；开发库只前向升级，不删除原事实或持久卷。

app 数据库账号是受信后端运行身份，业务操作者及 request-v1 摘要由验证当前 Bearer 会话的服务传入；数据库再次核对账户与任务身份，不替代 JWT 认证或独立重算 HTTP 摘要。共享 app 连接不映射为每名业务用户的 PostgreSQL 账号，运行凭据仅保存在本机受控配置中。

## 验收要求

独立随机 PostgreSQL 库验证跨用户全流程、拒绝自审与越权、UNKNOWN/非成功依据、冻结依据、幂等重放/内容冲突、终态/逻辑删除、两连接旧版本竞争、历史失败回滚和运行账号对象权限。迁移往返与已有阶段回归通过后，在真实后端连接的独立合成库进行桌面/窄屏浏览器验收；证据不得包含密码、JWT、连接串或真实人员明细。

方法依据：[PostgreSQL 17 函数安全](https://www.postgresql.org/docs/17/sql-createfunction.html)、[事务锁](https://www.postgresql.org/docs/17/explicit-locking.html)。实际执行结果写入 M5 里程碑记录，设计要求不等同于已经通过验收。
